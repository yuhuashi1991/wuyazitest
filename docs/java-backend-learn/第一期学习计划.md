# 第一期学习计划（第 1–7 天）

第一期对应 30 天课程的开篇关卡：**先看全景，再能看懂并跑起「订单管理 API」骨架**。本期只写第 1–7 天；后期（持久化深挖、测试体系、中间件生态、结业订单实战）不在此展开。每天约 2 小时，其中练习不超过 60 分钟。正式讲义仍等学员回复「开始第 1 天」后再按天发放，本文是计划与关卡，不是五天详细讲义打包。

对应总目标：优先落地「看懂目录和分层」，并为「需求如何变成接口 / 逻辑 / 表 / 测试」「在 AI 辅助下运行小型 Spring Boot 项目」打底。

---

## 1. 本期范围

**做：**

- 一张三层标注的 Java 后端全景地图（必须掌握 / 理解用途 / 暂时跳过）。
- 源码到运行：JDK、JVM、编译、运行。
- 在订单代码里补齐必要语法：类、对象、接口、继承、集合、泛型、异常、常用 Stream；不单开语法课。
- Maven、依赖、配置文件、常见项目目录。
- 分层职责与调用：`Controller`（vo）→ `Service`（接口 / `Impl`）→ `Dao`（po）→ `Mapper`（xml:sql）。
- REST / HTTP / JSON、参数校验、统一错误处理的最小可读路径。
- Spring Boot 最小可运行订单服务骨架（能启动、能打通一条读或写）。
- 向 AI 提供需求、代码上下文、错误信息、验收标准；识别虚构接口、改动过大、漏异常、「看起来正确」。
- 日志、断点、异常堆栈的入门定位（能跟着一次失败跑通）。

**明确标为「只建立认知，暂不深入」（本期不实现）：**

- Spring / SpringMVC / MyBatis / MyBatisPlus / SSM / Redis / SpringCloud 的完整原理与启动细节。
- Docker、Elasticsearch、Zookeeper、Nginx、SpringSecurity、RocketMQ、GitFlow、堡垒机。
- ELK 的使用分析。
- 事务与数据一致性的完整方案；并发、安全、缓存、消息队列、部署的实现。
- 结业级订单四件套（创建 / 查询 / 改状态 + 全套测试）的完整验收。

**不做：** 视频课、系统读书、从头背语法、无关算法题、一次丢出五天讲义。

贯穿场景：用户、商品、订单、库存；主线项目固定为订单管理 API。

## 2. Java 后端全景地图（本期先给这张）

读图规则：左到右是一次请求的路径；上到下是「你要看到多深」。标注对 **整个 30 天** 有效，第一期只走到「能指认 + 跑通骨架」。

```
浏览器 / 前端
    → HTTP + JSON（REST）
        → Nginx（本期：理解用途）
            → Spring Boot 进程（内嵌 Tomcat，DispatcherServlet / SpringMVC）
                → Controller（接收请求，VO 进/出）
                    → Service 接口 + Impl（业务规则、事务边界）
                        → Dao / Mapper（PO + XML SQL 或注解 SQL）
                            → 数据库
                横切：校验、统一错误处理、日志
旁路（本期大多只认名字）：Redis 缓存、RocketMQ、ES 搜索、SpringSecurity、ELK、Docker、注册配置（SpringCloud / Zookeeper）
底座：JDK 编译 → JVM 运行；Maven 管依赖与目录
```

| 层级 | 必须掌握（能讲清、能在项目里指出来、能验证） | 理解用途（知道解决什么问题、何时会用到） | 暂时跳过 / 只建立认知 |
| --- | --- | --- | --- |
| 运行底座 | JDK、JVM、javac/编译、运行、classpath 直觉 | JIT、字节码细节 | JVM 调优、类加载器实现 |
| 语言（在代码中认） | 类/对象/接口、继承、集合、泛型、异常、常用 Stream | 反射、注解的存在意义 | 字节码、复杂并发 API |
| 工程 | Maven、依赖、`pom.xml`、`src/main/java`、`resources`、测试目录、配置文件 | 多模块、私服 | Gradle、复杂 profile 矩阵 |
| Web 与 API | REST、HTTP 方法/状态码、JSON、参数校验、统一错误处理 | 内容协商、OpenAPI 生成 | 网关定制、GraphQL |
| 分层 | Controller / VO、Service / Impl、Dao / PO、Mapper XML | DTO 与 VO 的细微差别 | 复杂 DDD 战术设计 |
| 框架 | Spring Boot 能启动、自动配置「大概替你做了什么」 | Spring、SpringMVC、MyBatis / MyBatisPlus、SSM 各自职责与启动顺序直觉 | 手写 Spring、深入 Bean 生命周期 |
| 数据 | 一张订单表怎么对应 PO/SQL；主键、状态字段 | ORM、事务「要么全成要么全停」 | 分布式事务、锁实现 |
| 品质 | 看日志和异常堆栈、断点、用测试判断 AI 代码是否真可用 | 单元测试 vs 接口测试分工 | 覆盖率工具链、性能测试 |
| AI 协作 | 需求 + 上下文 + 报错 + 验收标准；防虚构、防大改、防漏分支 | — | — |
| 生态 | — | Redis、Docker、Nginx、SpringCloud、MQ、Security、ELK | ES/ZK/堡垒机/GitFlow 的操作与原理深挖；并发/安全/缓存/MQ/部署的实现 |

前端类比（只用于建立直觉，不是对等实现）：Controller ≈ 路由处理函数；Service ≈ 领域/用例逻辑；Mapper ≈ 访问数据库的 repository；`application.yml` ≈ 环境配置；Maven ≈ 带约定目录的包管理。

## 3. 按天安排

每天统一产出结构见《java学习任务说明.md》第 5 节（11 项）。下表只列关卡目标、概念、场景、练习与完成标准，不含完整代码讲义。

### 第 1 天｜全景地图 + 源码如何跑起来

- **地图位置：** 底座（JDK / JVM / 编译 / 运行）。
- **核心概念（3～5）：** JDK vs JVM；源码 → 字节码 → 运行；入口类与 `main`；为什么后端是「长期运行的进程」而不只是脚本。
- **业务场景：** 一台「订单服务」机器上，一次「查询订单」请求到达前，Java 进程必须已经在跑。
- **练习（≤60 分钟）：** 阅读一份最小 `main` 或 Spring Boot 启动类；预测「编译产物在哪、运行的是谁」；用 AI 只做一件事：在本机/沙箱跑通启动（或明确失败原因）。
- **指挥 AI：** 「不要改业务代码；只说明如何编译运行，并给出我可复制的命令与成功判据。」
- **完成标准：** 能用自己的话画出从 `.java` 到进程；能指出必须掌握 vs 暂时跳过；能力清单出现「能解释订单服务是一个 JVM 进程」。

### 第 2 天｜订单代码里的对象模型（语法只在现场补）

- **地图位置：** 语言层，落在「订单 / 用户 / 商品 / 库存」模型。
- **核心概念：** 类与对象；接口 vs 实现；集合（`List`/`Map`）；异常；常用 Stream（过滤/映射）。
- **业务场景：** `Order` 有状态；`OrderItem` 引用商品；库存不足要失败。
- **练习：** 读 1～2 个订单相关类；预测某方法在库存不足时抛什么、集合里如何查找；指挥 AI **小范围** 增加一个纯内存校验（如订单项不能为空），禁止重构全局。
- **完成标准：** 能在代码里指认接口、实现、集合和抛出点；能说明 AI 在此处常漏边界；不要求背 API 列表。

### 第 3 天｜Maven、依赖、目录、配置

- **地图位置：** 工程骨架。
- **核心概念：** 约定目录；`pom.xml` 依赖；`application.yml` / `properties`；主代码 vs 测试代码；构建 vs 运行。
- **业务场景：** 前端熟悉「一个仓库多个文件夹」；Java 后端用 Maven 约定告诉你 Controller 和配置各在哪。
- **练习：** 对照一棵典型 Spring Boot 树，标注 `controller` / `service` / `mapper` / `resources`；指挥 AI 添加一个无害依赖或配置项并说明会改哪些文件。
- **完成标准：** 合上电脑能默画常见目录；能指出「只改配置却让 AI 重写业务」是错误指挥。

### 第 4 天｜分层：Controller → Service → Dao → Mapper

- **地图位置：** 请求主链路（本期核心）。
- **核心概念：** VO 进 Controllers；Service 接口 + `Impl`；PO 与 Dao；Mapper XML 中的 SQL；调用方向只朝下。
- **业务场景：** 「查询订单」从 HTTP 进，经过校验与业务，落到一条 SELECT。
- **练习：** 读一条查询链路的四个文件，画出调用图；故意打乱一层职责，说明为什么难测、难改；指挥 AI **只改 Service 一层** 的注释或校验，验收「Controller 与 Mapper 无 diff」。
- **完成标准：** 能口述四层职责和数据形态（VO / 领域对象 / PO）；能发现「Controller 里写 SQL」或「Mapper 里做价格计算」这类错位。

### 第 5 天｜REST、HTTP、JSON、校验、统一错误

- **地图位置：** 前端最熟的边界。
- **核心概念：** 资源与 HTTP 方法；状态码；JSON 字段；参数校验；统一错误体。
- **业务场景：** 创建订单失败（缺字段 / 非法状态）时，前端应收到稳定错误而不是堆栈。
- **练习：** 读一个 Controller 方法的入参出参；预测 400 vs 404 vs 500；指挥 AI 为「创建订单」补一条校验 + 错误响应，禁止改数据库结构。
- **完成标准：** 能把产品话术翻成「方法 + 路径 + 请求体 + 错误码」；检查清单能抓住 AI 虚构未存在的接口路径。

### 第 6 天｜Spring Boot 最小可运行订单骨架

- **地图位置：** 框架「能启动」；MyBatis 等只点名。
- **核心概念：** Spring Boot 启动类；自动配置直觉；一条 API 从注解到返回；「能跑」≠「业务对」。
- **业务场景：** 启动订单服务后，查询或创建一个内存/本地存储订单并看到 JSON。
- **练习：** 在 AI 辅助下启动项目；用一次 HTTP 调用验证；根据日志或堆栈修一个启动/端口/依赖问题（真实或注入的）。
- **完成标准：** 独立复述启动命令与成功判据；能指出 SpringCloud / Redis / MQ 本期不用接。

### 第 7 天｜第一期检查点（合关，不新开生态）

- **地图位置：** 回顾第 1–6 天走过的主链路。
- **核心概念：** 用六问复盘一个点（建议：分层或校验）；AI 验收标准；能力清单。
- **业务场景：** 产品说「先能查到订单，创建先做最小字段」。
- **练习：** 限时走查目录 + 分层；指挥 AI 做一处符合验收清单的小改动；用检查清单判定是否可合并。
- **完成标准：** 见第 5 节检查点。不开始 Docker / MQ / ELK。

## 4. 练习任务总表（第一期）

| 天 | 代码阅读 | 指挥 AI（必须带验收） | 刻意限制 |
| --- | --- | --- | --- |
| 1 | 启动类 / 最小入口 | 只解决「如何运行」 | 不改业务 |
| 2 | 订单相关类 | 纯内存校验小补丁 | 不准全局重构 |
| 3 | 目录与 `pom` / 配置 | 加配置或依赖并列出文件清单 | 不准顺便升级框架 |
| 4 | 四层查询链路 | 只改 Service | Controller 与 Mapper 无 diff |
| 5 | Controller 入出参 | 校验 + 统一错误 | 不改表结构、不虚构路径 |
| 6 | 启动与一次 HTTP | 跑通并修启动问题 | 不接 Redis/MQ/Cloud |
| 7 | 全目录走查 | 一处可合并小改动 | 对照检查点六条 |

每日另有 5 道理解题（开课后按天出，先作答再公布）。练习超时就减范围，不把算法题塞进来凑时长。

## 5. 第一期检查点（关卡「完成」）

同时满足以下条件，才算第一期过关（不是 30 天结业）：

1. **地图：** 能指认必须掌握 / 理解用途 / 暂时跳过三类，且不把 Redis、SpringCloud、ELK 说成「这周必须实现」。
2. **运行：** 能说明 JDK/JVM/编译/运行在订单服务里各扮演什么；知道成功启动的判据。
3. **目录：** 打开一个常见 Maven + Spring Boot 树，能标出主代码、资源、测试、Controller / Service / Mapper 大致位置。
4. **分层：** 能沿「查询订单」画出 `Controller(vo) → Service/Impl → Dao(po) → Mapper(xml)`，并指出一层越权的例子。
5. **边界：** 能把「查订单 / 最小创建」说成 HTTP + JSON，并说明校验失败应走统一错误而不是裸堆栈。
6. **AI：** 能写一条含需求、涉及文件、禁止事项、验收标准的指令；能用清单抓住虚构接口、改动过多、漏异常或「看起来能跑」。

未过关则第 8 天仍留在骨架，不进入后期主题。30 天总结业（需求完整、分层合理、状态流转、事务一致性风险、异常覆盖、测试是否验证业务规则）不在第一期验收。

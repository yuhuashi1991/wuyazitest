# Java 后端学习任务说明

本文是对学员原始任务简报的结构化复述，不增加与原文冲突的要求。完整 30 天课程尚未开课：先建立全景与计划，等学员回复「开始第 1 天」后再按天教学。

## 1. 学员与受众

- 职业是前端工程师，目标不是转成传统「从零背语法」的 Java 新手。
- 已有一些 Java 基础语法：变量、条件、循环、方法、简单的类。
- 学习目的：以后更高效地用 AI 编写、修改和检查 Java 项目。
- 教学口吻：面向前端工程师建立技术全局观；用准确但通俗的中文，必要英文术语放在括号中。

## 2. 总目标与时间盒

用 **30 天、每天约 2 小时**，建立 Java 后端开发的整体认知。

学完后应能做到：

1. 看懂一个常见 Java 后端项目的目录和分层。
2. 理解一项产品需求如何变成接口、业务逻辑、数据表和测试。
3. 看懂 AI 生成的大部分常规 Java 代码，并发现明显问题。
4. 准确地要求 AI 新增功能、修改代码、修复 Bug 和补充测试。
5. 能在 AI 辅助下运行一个小型 Spring Boot 微服务项目，并验证结果。
6. 知道哪些内容必须理解，哪些只需知道用途，哪些可以暂时跳过。

信息密度控制：优先讲最重要的约 20%，用来覆盖实际工作中约 80% 的 Java 后端问题。

## 3. 硬约束（怎么学、不怎么学）

- 不看视频、不系统读书、不从头背语法。
- 不采用传统教材式知识罗列。
- 不从基础语法重新讲起；只在实际代码里补充必要语法。
- 不要求机械背诵；不安排与上述目标无关的算法题。
- 少讲抽象定义；多用最小可运行代码、类比、代码阅读和任务驱动。
- 使用前端熟悉的业务场景：用户、商品、订单、库存。
- 围绕一个贯穿始终的小型业务项目，优先「订单管理 API」。
- 每次练习控制在 **60 分钟**。
- 不要一次输出五天的全部详细讲义；按天、按关卡互动。
- 若某内容无法在 5 天内掌握，明确标为「只建立认知，暂不深入」。

## 4. 每个知识点必须交代的六问

讲任何一个知识点时，都要说明：

1. 它解决什么问题。
2. 它在项目中的位置。
3. 前端工程师需要理解到什么程度。
4. 使用 AI 时应该怎样描述需求。
5. AI 最容易在这里犯什么错误。
6. 我应该如何验证。

## 5. 每天的输出格式（开课后）

1. 今日目标
2. Java 全景地图中的当前位置
3. 3～5 个核心概念
4. 一个业务场景
5. 最小可运行代码
6. 代码阅读任务
7. 一个让我指挥 AI 完成功能的任务
8. 验证 AI 结果的检查清单
9. 5 道理解题
10. 今日完成标准
11. 哪些内容暂时不用学

## 6. 教学过程约定

- 先让学员预测或尝试，再公布答案。
- 答错时指出认知缺口，不要只给正确答案。
- 每天结束根据当天表现调整下一天内容。
- 每完成一天，更新一张「我已经能做什么」能力清单。
- 先给一张「Java 后端全景地图」，再进入每天的学习。
- 全景地图需标注：**必须掌握**、**理解用途**、**暂时跳过**。

## 7. 课程至少覆盖的主题

下列条目均来自原始简报；深度按「必须掌握 / 理解用途 / 暂时跳过」分层，不能在 5 天内掌握的标为只建立认知。

- Java 程序从源码到运行：JDK、JVM、编译、运行。
- 类、对象、接口、继承、集合、泛型、异常和常用 Stream 操作。
- Maven、依赖、配置文件和常见项目目录。
- 微服务核心：Spring、SpringMVC、MyBatis、MyBatisPlus、SSM、Redis、Spring Boot、SpringCloud 的工作原理 / 作用 / 启动过程。
- 分层与调用：`Controller`（vo）→ `Service`（接口定义 / `Impl`）→ `Dao`（接口定义：po）→ `Mapper`（xml:sql）。
- 微服务生态：Docker、Elasticsearch、Zookeeper、Nginx、SpringSecurity、RocketMQ、GitFlow、堡垒机等工作原理 / 作用 / 启动过程。
- REST API、HTTP、JSON、参数校验和统一错误处理。
- ELK 日志管理的使用分析。
- 数据库、SQL、ORM、事务以及常见数据一致性问题。
- 日志、断点、异常堆栈和常见 Bug 定位方法。
- 单元测试、接口测试，以及如何判断 AI 的代码是否真的可用。
- 并发、安全、缓存、消息队列和部署的基本认知，但不要求深入实现。
- 如何向 AI 提供需求、代码上下文、错误信息和验收标准。
- 如何防止 AI 虚构接口、修改过多代码、遗漏异常分支或只给出「看起来正确」的代码。

## 8. 贯穿项目与最终实战

贯穿项目：小型「订单管理 API」。

最终在 AI 辅助下完成，至少包括：

- 创建订单
- 查询订单
- 修改订单状态
- 参数校验
- 数据存储
- 异常处理
- 自动化测试

## 9. 什么叫「整课完成」（结业标准）

不能只检查代码能否运行，还要检查：

- 需求是否完整
- 分层是否合理
- 状态流转是否正确
- 事务和数据一致性是否存在风险
- 异常场景是否覆盖
- 测试是否真正验证业务规则

同时对照第 2 节六条能力：目录分层、需求落地路径、读 AI 代码并找明显问题、准确指挥 AI、跑通小型 Spring Boot 服务并验证、分清必须理解 / 只需用途 / 可跳过。

## 10. 当前停在哪

按原始简报，开课前只做两件事：

1. 给出简洁的 Java 后端全景地图，并标注必须掌握、理解用途、暂时跳过。
2. 给出训练安排、每天的产出和结业标准。

其中「第一期」学习计划见同目录《第一期学习计划.md》。第一期只覆盖开课前地图与第 1–7 天骨架关卡，不展开后期天次的详细讲义。

完成后停下来，等学员回复 **「开始第 1 天」**，再正式按天教学。
